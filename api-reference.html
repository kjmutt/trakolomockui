REST API reference
Every call to apps/api — from the React SPA or a third-party integration — goes through the API Gateway described in Application architecture. This page documents that surface: base URL, auth, versioning, rate limits, and the endpoints themselves.
Application architecture → Download openapi.yaml →
In one line
One versioned REST API (/api/v1) behind the gateway, OAuth2 bearer tokens for the SPA and API keys for integrations, cursor-based pagination, RFC 7807 error bodies, and per-tenant rate limits enforced at the gateway — not scattered per module.
Conventions
Base URLhttps://{tenant}.trakolo.com/api/v1
Auth — user sessionsOAuth2 bearer token, issued at sign-in (login.html), validated at the gateway before the request reaches apps/api
Auth — integrationsAuthorization: ApiKey <key>, issued from Admin → Integrations, scoped to specific modules
Versioning/api/v1 today. Changes are additive only (new fields, new endpoints); a breaking change ships as /api/v2 with v1 kept live through its deprecation window — same rule as the canary/rollback discipline in Release & DR.
Rate limitsEnforced per tenant at the gateway, scaled by plan tier — exceeding it returns 429 with a Retry-After header, not a silently dropped request.
PaginationCursor-based: ?cursor=<opaque>&limit=50 (max 200), response includes next_cursor
ErrorsRFC 7807 application/problem+json — {type, title, status, detail, instance}, never a bare string
Endpoints — itsm
MethodPathDescription
GET/ticketsList tickets, filterable by status/priority/category_id/assignee
POST/ticketsCreate a ticket
GET/tickets/{id}Get a single ticket
PATCH/tickets/{id}Update status, assignee, category, priority
GET/tickets/{id}/activityActivity feed — comments, status changes, AI agent actions
POST/tickets/{id}/attachmentsUpload an attachment
GET/ticket-categoriesTree of ticket categories — see Entity relationships
GET/kb-articlesList/search knowledge-base articles
POST/kb-articlesCreate a KB article
GET/service-catalog-itemsList catalog items available to request
POST/catalog-requestsSubmit a service catalog request
GET/change-requestsList change requests
POST/change-requests/{id}/approvalsRecord an approval decision
GET/problemsList problem records and their linked incidents

Field names mirror db/schema.sql directly — category_id is expanded to a nested category object in responses, but the underlying column and the hierarchical itsm.ticket_categories table are exactly what Entity relationships documents.
